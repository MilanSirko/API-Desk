MAKING A REQUEST

Request settings

Control how the request behaves when the API is slow, redirects, or returns transient server errors.

Timeout

The request timeout controls how long the client waits before aborting the request. The default is 30000 ms (30 seconds).

Use a shorter timeout for fast-failing calls, or a longer one for slower APIs.

Retry count

Retry count defines how many times APIDesk retry the request after a retryable failure. The default is 0, and the maximum value in the UI is 5.

Retries are only used for safe, idempotent request types and only for specific failures.

Retry delay

The delay between retries is configured in milliseconds. The default is 500 ms, and the minimum is 0.

Use this to avoid hammering an API that is temporarily failing or overloaded.

Follow redirects

When enabled, the browser follows HTTP redirect responses automatically. This option is checked by default.

Disable it if you want to inspect the redirect chain or avoid automatic navigation between endpoints.

Max response

Max response limits how large a response body the client accepts before stopping. The default is 10 MB, and the upper limit in the UI is 1024 MB.

This helps prevent large downloads from consuming too much memory or making the workspace unusable.

i

Retry rule: APIDesk retries only for methods GET, HEAD, OPTIONS, PUT, and DELETE. It retries only when the response status is 502, 503, or 504, or when there is a network failure.

Default values at a glance

Timeout

Default: 30000 ms

Retry count

Default: 0, max: 5

Retry delay

Default: 500 ms, min: 0

Follow redirects

Default: enabled

Max response

Default: 10 MB, max: 1024 MB
