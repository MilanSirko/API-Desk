Frequently asked questions

Answers to the most common questions about APIDesk, request setup, auth, collections, and session behavior.

What is APIDesk?

APIDesk is a browser-based API testing workspace for building requests, reviewing responses, and saving reusable collections and folders.

Why is my request failing?

Common causes include a wrong URL, incorrect method, missing headers, invalid auth, or a CORS restriction from the target API. Check the response status and request logs to narrow it down.

What is the difference between a collection and a folder?

A folder is used for organization. A collection groups related requests and can include shared settings that apply across its requests.

How do shared variables and headers work?

Shared settings are defined at the collection level and can be reused across requests. Request-level values still override collection-level values when both define the same item.

What happens when my session expires?

If the current access token is no longer valid or refresh fails, the session is ended and APIDesk asks you to log in again before protected requests can continue.

Where are tokens and passwords stored?

Active session data is stored in the browser so the current sign-in can remain available while the session is active. The backend is responsible for validating auth and managing session lifecycle.

Can I import an OpenAPI document?

Yes. APIDesk supports OpenAPI import and export flows through the Import and export feature, which can turn an OpenAPI 3.x file into request definitions and save them in the workspace.

Does APIDesk support Google or GitHub login?

Only when the backend is configured for OAuth. If the backend supports Google or GitHub login, those options appear in the auth flow. Otherwise, email and password login remains the standard option.
